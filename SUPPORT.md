# Support and Escalation

We want you to get help quickly and efficiently. Choose the option that best fits your request.

## Self-service
- Review project READMEs and troubleshooting sections.
- Search existing [issues](../../issues) and discussions for similar questions.
- Consult CHANGELOGs or release notes for recent behavior changes.

## How to ask for help
- For **how-to questions** or **design advice**, open a GitHub Discussion or issue with the `question` label and include logs, configuration, and steps already taken.
- For **bug reports**, use the "Bug Report" issue template so maintainers can reproduce and prioritize the problem.
- For **feature requests**, use the "Feature Request" template and focus on the user problem, success criteria, and alternatives considered.

## Security and privacy
Do **not** post sensitive information or security vulnerabilities in public issues. Email `security@c-tech-labs.com` per the [Security Policy](SECURITY.md).

## Production incidents
If you are experiencing a production outage or severe degradation:
1. Open a high-priority issue using the bug template and set severity to `critical`.
2. Page the on-call/responder through your team’s agreed channel (Slack, PagerDuty, or email).
3. Provide dashboards, logs, and timeframes so responders can investigate quickly.

## Service level expectations
- **Issue triage:** new issues are reviewed within **2 business days**.
- **Severity guidance:** blockers and regressions are prioritized first; feature requests are scheduled based on roadmap capacity.
- **Communication:** maintainers will update issues after meaningful investigation steps or when an ETA is available.

## Contact
- **General questions:** create a Discussion or issue with the `question` label.
- **Security:** email `security@c-tech-labs.com`.
- **Partnership or roadmap inquiries:** contact the maintainers listed in repository metadata or open a Discussion tagged `governance`.
